# Календарь справедливости

Мобильное приложение на HTML, CSS и JavaScript без библиотек и фреймворков. Оформление рассчитано на телефоны и планшеты. При запуске тема выбирается по настройке устройства; в настройках приложения можно вручную включить светлую или тёмную тему.

## Запуск

Открывайте проект через локальный HTTP-сервер, например Live Server в VS Code: откройте папку проекта, нажмите правой кнопкой на `index.html` и выберите **Open with Live Server**.

Адрес страницы должен начинаться с `http://`, например `http://127.0.0.1:5500`. При открытии файла двойным щелчком через `file://` браузер может блокировать подключение ES-модулей, и кнопки не будут работать.

## Файлы и папки

- `index.html` — разметка двух экранов: `calendarScreen` и `settingsScreen`. Содержит верхнюю панель календаря, нижнюю навигацию, пустой контейнер списка участников и общее окно редактирования `participantDialog`. Подключает три CSS-файла и шесть JavaScript-файлов через `type="module"`. Данные участников в HTML не дублируются.
- `src/css/main.css` — общие цвета, светлая и тёмная темы, шрифт, размеры страницы, безопасные отступы для мобильных экранов, нижняя навигация и класс скрытия `.screen-hidden`.
- `src/css/calendar.css` — оформление верхней панели и календарной сетки из семи колонок.
- `src/css/settings.css` — оформление раздела участников, строк списка, цветных кружков, кнопок «Изменить» и всплывающего окна с полями имени и цвета.
- `src/js/app.js` — инициализация переключателя темы и применение ручного выбора ко всему приложению.
- `src/js/calendar.js` — экспортирует `renderCalendar(year, month)`, выводит календарную сетку и обрабатывает переходы к предыдущему и следующему месяцу.
- `src/js/rotation.js` — пока пустой файл для будущей логики чередования участников.
- `src/js/persons.js` — стандартные данные, загрузка и экспорт массива `persons`, создание списка, редактирование имени и цвета с автоматическим сохранением.
- `src/js/storage.js` — функции `savePersons(persons)` и `loadPersons()` для записи и чтения участников в `localStorage`.
- `src/js/navigation.js` — обработка кнопок нижней навигации и переключение видимого экрана.
- `src/assets/icons/` — пока пустая папка для иконок. Текущие иконки навигации записаны как SVG прямо в `index.html`.
- `README.md` — описание текущего устройства проекта и поведения кода.

## Данные участников

Стандартный массив `defaultPersons` в `persons.js` содержит четыре объекта. Экспортируемый массив `persons` получает сохранённые данные, а если их нет или они некорректны — стандартные:

- `id` — числовой идентификатор участника.
- `name` — отображаемое имя.
- `color` — цвет в формате HEX (`#rrggbb`), подходящем для `input type="color"`.
- `active` — признак активности. У всех участников сейчас `true`; в текущей логике он ещё не используется.

Начальные имена — «Участник 1», «Участник 2», «Участник 3», «Участник 4». Их цвета — красный, синий, зелёный и жёлтый соответственно. Массив экспортируется через `export const persons`. Объекты внутри него можно изменять.

## Как работает JavaScript

Код использует обработчики событий в `addEventListener`, перебор массивов и функции `applyColor` и `updateColorSelection` для выбора цвета. Их назначение описано ниже.

### Переключение экранов — navigation.js

1. `navigationButtons.forEach` назначает обработчик `click` каждой кнопке навигации.
2. Обработчик `click` читает `aria-controls` нажатой кнопки: это ID экрана, который нужно показать.
3. Внутренний `screens.forEach` добавляет класс `screen-hidden` невыбранному экрану и убирает его у выбранного. CSS-класс задаёт `display: none`.
4. Внутренний `navigationButtons.forEach` устанавливает `aria-current="page"` выбранной кнопке и удаляет атрибут у другой. Это обновляет подсветку и обозначает текущий экран для средств доступности.

При первом открытии виден `calendarScreen`. Начальное скрытие `settingsScreen` задано классом в HTML.

### Календарная сетка — calendar.js

`renderCalendar(year, month)` принимает год и номер месяца в формате JavaScript: январь — `0`, декабрь — `11`. Функция форматирует заголовок на русском языке, очищает прежнюю сетку и создаёт семь заголовков: Пн, Вт, Ср, Чт, Пт, Сб, Вс.

Первый день месяца определяется через `Date.getDay()`. Формула `(day + 6) % 7` переводит стандартный отсчёт с воскресенья на понедельник. До первого числа функция добавляет нужное количество пустых ячеек, а затем все числа месяца. Количество дней вычисляется через последний день выбранного месяца, поэтому учитываются месяцы разной длины и високосные годы.

При загрузке функция вызывается для текущего месяца. Переменная `displayedMonth` хранит первый день показанного месяца. Обработчики кнопок вызывают `changeMonth(-1)` или `changeMonth(1)`.

`changeMonth(offset)` создаёт новую дату со сдвигом на указанное количество месяцев и повторно вызывает `renderCalendar()` с обновлёнными годом и месяцем. Объект `Date` автоматически выполняет переход между декабрём и январём. Заголовок обновляется внутри `renderCalendar()`. Цветные кружки и события календаря не добавляются.

### Выбор темы — app.js

В `index.html` на экране настроек есть раздел «Тема» с радиокнопками «Светлая» и «Тёмная». Их оформление находится в `settings.css`.

`updateThemeSelection(theme)` отмечает соответствующую радиокнопку. При загрузке `matchMedia` определяет тему устройства. Обработчик `change` радиокнопки записывает ручной выбор в атрибут `data-theme` элемента `html`. Правила в `main.css` меняют общие цвета и `color-scheme`, включая оформление нативных полей.

Обработчик `change` у `systemTheme` обновляет отмеченную радиокнопку при смене системной темы, пока пользователь не сделал ручной выбор. Ручной выбор действует до перезагрузки и не сохраняется в `localStorage`.

### Создание списка — persons.js

`persons.forEach` выполняется при загрузке модуля и создаёт для каждого участника строку `li`: цветной кружок, имя и кнопку «Изменить». Строки добавляются в `participantsList`. Имя задаётся через `textContent`, поэтому введённый текст не интерпретируется как HTML.

### Открытие редактора — обработчик click кнопки «Изменить»

Обработчик сохраняет в `editingParticipant` ссылку на объект участника и его элементы в списке. Затем заполняет поля текущими именем и цветом, сбрасывает прежнюю ошибку проверки имени и открывает общее окно методом `showModal()`.

`editingParticipant` равен `null`, когда никто не редактируется. Ссылки на элементы позволяют обновлять только выбранную строку без создания всего списка заново.

### Изменение имени — обработчик input у nameInput

Удаляет пробелы по краям введённого имени через `trim()`. Непустое имя сразу записывается в `person.name`, отображается в строке и обновляет доступное название кнопки «Изменить». Затем `savePersons(persons)` сохраняет массив в `localStorage`.

Пустое имя или одни пробелы не заменяют прежнее значение. `setCustomValidity()` задаёт сообщение об ошибке, а проверка формы не позволяет закрыть окно кнопкой «Готово», пока имя не исправлено.

### Изменение цвета — обработчик input у colorInput

В окне показаны четыре стандартных цвета: красный, синий, зелёный и жёлтый. Справа находится круг с радужной рамкой и знаком «+» для выбора своего цвета через `input type="color"`. Выбранный стандартный цвет отмечается обводкой.

`presetColors` в `persons.js` хранит фиксированную палитру. `presetColors.map` создаёт кнопки в контейнере `presetColors` и назначает каждой обработчик `click`. Палитра не зависит от изменения цветов участников. Её оформление находится в `settings.css`.

Плюс в радужном круге нарисован двумя CSS-псевдоэлементами и расположен точно по центру, независимо от шрифта устройства.

`applyColor(value)` вызывается при нажатии готового цвета или событии `input` у поля своего цвета. Она сразу записывает цвет в `person.color`, меняет кружок выбранного участника, вызывает `updateColorSelection(value)` и сохраняет массив через `savePersons(persons)`.

`updateColorSelection(value)` синхронизирует нативное поле цвета и атрибуты `aria-pressed` кнопок палитры. Она также вызывается при открытии редактора. Если выбран свой оттенок, не совпадающий со стандартными, обводка снимается со всех четырёх кнопок. Остальные участники не изменяются.

### Закрытие окна — обработчик close у participantDialog

Кнопка «Готово» закрывает окно средствами HTML-формы с `method="dialog"`. Окно также можно закрыть клавишей Escape. Обработчик `close` очищает `editingParticipant`.

Имя и цвет применяются уже во время ввода. Закрытие окна, в том числе через Escape, не отменяет применённые изменения. Отдельного сохранения по кнопке «Готово» нет.

## Что реализовано сейчас

Есть два экрана, переключение между ними, календарная сетка с неделей от понедельника и переходами между месяцами, ручной выбор светлой и тёмной темы, список четырёх участников и редактирование их имени и цвета. Участники автоматически сохраняются и восстанавливаются после перезагрузки. Цветные отметки, события календаря и логика чередования ещё не реализованы. События календаря не сохраняются. Тема по-прежнему возвращается к системной после перезагрузки.

## Сохранение участников — storage.js

`savePersons(persons)` преобразует массив в JSON и записывает его в `localStorage` под ключом `justiceCalendar.persons`. Возвращает `true` при успешной записи. Если браузер запрещает хранение или место закончилось, выводит предупреждение в консоль и возвращает `false`; интерфейс продолжает работать, но изменения могут не сохраниться.

`loadPersons()` читает этот ключ, разбирает JSON и проверяет данные: от одного до четырёх участников, уникальные положительные целочисленные ID, непустые имена, HEX-цвета и логические значения `active`. Возвращает массив либо `null`, если записи нет, данные некорректны или хранилище недоступно.

При запуске `persons.js` вызывает `loadPersons()` до создания списка. При результате `null` используется `defaultPersons`. При каждом принятом изменении имени или цвета сохраняется весь текущий массив. Кнопка «Готово» только закрывает окно.

Данные привязаны к адресу сайта и браузеру: для восстановления открывайте приложение с тем же протоколом, хостом и портом. Тема и события календаря в эту запись не входят.
